3 Problem

Imperative scripts don't scale with the fleet

Before · imperative push
  • System knows scripts finished, not what's running
  • Config hand-edited on each node
  • Rendered twice; the real script is in no repo
  • Drift and stale objects go unnoticed

  • Git holds desired state
  • Argo CD continuously reconciles
  • Per-cluster diff is a reviewed file
  • Every resource: in sync, or a visible diff

not a runbook.

5 System design

Why Argo CD agent mode

Classic hub-and-spoke
  • One central controller does all reconciliation
  • Hub holds API credentials for every cluster
  • Hub must reach into each cluster
  • Hub down → whole fleet stops reconciling
→
Agent (what we chose)
  • Each cluster reconciles locally
  • Agent dials out; no inbound, no stored kubeconfigs
  • Hub down → clusters keep converging
  • Watch and cache load distributed
ScalabilityFault toleranceSecurityLower latencyNo hub bottleneck

The cost

One more component per cluster to deploy, upgrade, and monitor.

5 System design

GitOps all the way down

Root app-of-apps · one per environment

root-dev   → watches dev:/appsets/* root-stage → watches stage:/appsets/* root-prod  → watches main:/appsets/*
Adding an app = committing an ApplicationSet. No more manual applies.

Argo CD manages itself

  • Upgrades, controller scaling, limits, security config
  • All as reviewed commits
Risk: a bad commit can break the fixer. → documented break-glass manual recovery.
Install Argo, apply the root app once.
Everything after that is a commit.
